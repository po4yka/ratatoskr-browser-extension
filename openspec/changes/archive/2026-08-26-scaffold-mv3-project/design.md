## Context

See proposal.md. Constraints that shape the design: the fleet gate turns on the moment `package.json` is tracked (it then demands `eslint.config.*`, and a `ci.yml` whose command list runs tests); DEVELOPMENT.md requires the first scaffold PR to document exact commands; QUALITY_GATES.md requires size limits carried in the ESLint configuration with measured numbers; AGENTS.md forbids broad permissions, remote code, and unpinned dependencies.

## Goals / Non-Goals

**Goals:**

- One npm package at the repository root with scripts for install, lint, typecheck, test, build, package, and a single `gate` script that runs them all in order.
- Deterministic build output and byte-stable zip packaging verified by an in-suite golden test.
- Tests that observe behaviour from outside (read files, run scripts, compare digests) so each test-first pair can fail for its stated reason before implementation exists.
- A CI workflow shaped like the fleet's existing repositories: SHA-pinned actions, minimal permissions, concurrency, timeout, and a final step asserting ci.yml's commands match DEVELOPMENT.md.

**Non-Goals:**

- No capture logic, no tab/page/selection access, no network code, no storage schema — later plan items.
- No UI framework choice yet; stubs are vanilla TypeScript + HTML so the framework decision lands with the first real popup work (plan item 2) instead of being speculative configuration now.
- No Firefox-specific packaging yet; manifest stays Chromium-MV3-shaped with adapters deferred per README architecture notes.
- No npm workspaces / apps-packages split; the monorepo layout arrives when a second package actually exists.

## Decisions

- **Build tool: esbuild driven by a small Node script, not Vite/@crxjs/Wxt.** The scaffold needs three tiny entry points bundled deterministically. esbuild has a small dependency tree, no config file magic, and gives full control over output naming (fixed names, no hashes), which deterministic packaging requires. @crxjs/Vite brings hash-named chunks and a large plugin surface; Wxt is a framework opinion we do not need yet. The script copies the hand-written manifest and static assets verbatim.
- **Manifest authored by hand as `src/manifest.json`.** A reviewed diffable file beats a generated one for permission audits; the build only copies it. A test reads it back so drift is caught regardless of how it was edited.
- **Deterministic zip via fflate with fixed metadata.** Entries are added in sorted path order, every entry timestamp is pinned to a constant epoch, external attributes are fixed, and compression level is pinned; fflate is dependency-free and lets us set these explicitly. Alternatives: invoking system `zip` (non-portable flag surface, locale/order hazards) or archiver (does not expose per-entry mtime cleanly). The golden test packages twice in separate child processes and compares SHA-256, which catches nondeterminism across process boundaries rather than only within one call.
- **Black-box tests over unit imports.** Vitest specs read `src/manifest.json` from disk, execute `scripts/build.mjs` / `scripts/package.mjs` via child processes against temp directories, and parse outputs. This makes the failing-test-first pairs fail with "file not found" / "script exited non-zero" — exactly the stated reason — instead of a module-resolution error, which the repo rules call out as an invalid failure mode. Pure logic that later grows inside src modules gets conventional unit imports at that point.
- **Size limits adopt the ratatoskr-web numbers** (`max-lines` 200, `max-lines-per-function` 120, `complexity` 8, `max-params` 2, all `error`, blank/comment lines skipped). One standard across the fleet's TypeScript repositories is cheaper than two divergent ones, and the empty tree trivially satisfies them; raising a number later is a documented measurement, per QUALITY_GATES.md policy.
- **Gate parity as a repository test**, mirroring the Rust repos' "workflow matches DEVELOPMENT.md" step: `tests/gate-parity.test.ts` extracts the fenced command list from DEVELOPMENT.md and compares it with package.json scripts, so the documentation cannot silently rot while CI stays green.
- **CI: checkout + setup-node only, both SHA-pinned; `npm ci`; run gate commands; parity self-check step.** No caching actions (supply-chain surface for seconds saved on a ~30s job); Node version pinned via `.nvmrc`; lockfile committed and `npm ci --frozen-lockfile` enforces it.
- **Permissions baseline is empty.** Nothing in the scaffold needs any permission. Plan item 3 adds messaging permissions with its own snapshot update. The snapshot test documents itself as the update point.
- **Icons are committed PNG fixtures** generated once by a throwaway local step, never regenerated by the build, so packaged bytes depend only on tracked files.
- **web-ext lint stays out of the automated gate for this milestone.** The CSP/no-remote-code invariant is enforced here by the manifest-CSP test plus review checklist; adding web-ext means a heavyweight dev dependency tree, and the scope marks it "where available". Recorded as follow-up, not silently dropped.

## Risks / Trade-offs

- [fflate output could change across versions] → fflate is pinned by the committed lockfile; the golden test fails loudly on any drift after a deliberate bump.
- [esbuild minor releases could alter emitted bytes] → same answer: lockfile pin + golden test; build determinism matters within a locked toolchain, which is what release builds use.
- [Empty-permissions baseline may look like a mistake to reviewers] → the snapshot test message states the policy and points to the spec requirement.
- [Single-root package may need restructuring into workspaces later] → accepted; moving directories is mechanical while speculative workspace config would be dead weight now.
- [zizmor pedantic findings on the new workflow] → follow the fleet conventions exactly (pinned SHAs, permissions block, concurrency, timeout) and audit locally with zizmor before pushing.
